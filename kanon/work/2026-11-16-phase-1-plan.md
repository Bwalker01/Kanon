# Phase 1: Core Engine

> **Summary:** Build the `kanon` command: project setup, templates, the review loop, approvals,
> verification and cost reporting, then prove it on two real requirements in this repository.
> **Decision:** Plan approved by the owner on 2026-11-16 (R-2). Build in progress.

## 1. Plan

### 1.1 Outcome

After Phase 1, `kanon init` prepares any Git repository for Kanon. A request made in Claude Code
then passes through the full loop: requirement, plan, build, independent review, correction,
documentation and owner approval. `kanon verify` fails if any step is missing.

### 1.2 Scope

| In scope | Out of scope (phase) |
|---|---|
| `kanon` package and command | Pinax tickets and roster (2) |
| Templates and setup | GitHub Projects (2), pull requests (3) |
| Review loop as Claude Code skills | Pantheon marketplace (4) |
| Approvals, verification, cost reporting | Headless engine mode (3) |

### 1.3 Work Items

| ID | Item | Delivers | Acceptance (a wrong result fails) |
|---|---|---|---|
| P1-01 | Package | `kanon-engine` (Python 3.11+, MIT), `kanon --version`, test suite | `uv tool install .` then `kanon --version` matches `pyproject.toml`; tests pass |
| P1-02 | Templates | Work file, decision, `REVIEW.md`, `STATUS.md`, documentation; frontmatter schema; person profile in `kanon.toml` | Every template validates; removing any required field fails naming the field |
| P1-03 | `kanon init` | Creates the ADR-009 layout, `AGENTS.md` section, `CLAUDE.md`, the conduct standard; asks the technical-level question | Empty repo receives exactly the expected files; a second run changes nothing; existing files are never overwritten |
| P1-04 | `kanon verify` | Work file sections present and ordered; plan committed before build; reviewer differs from creator; valid approvals; round limit; frontmatter; writing check; questions not deferred to review | One passing fixture; for each rule, a fixture breaking only that rule fails and names it |
| P1-05 | Approvals | `kanon approve` and `kanon request-changes` with hash of approved material; Claude Code permission rules | Changing approved material fails `verify`; a self-approval attempt in Claude Code is refused; remaining bypasses are tested and documented |
| P1-06 | Core roles | Coordinator (Metis), Reviewer (Kritos), Scribe (Clio), Context keeper (Mnemon) as neutral prompts with thin Claude Code wrappers; reviewer as read-only subagent | Agent Skills naming rules pass; wrappers at most 30 lines; reviewer has no write tools; writing review fails a seeded document and passes a clean one |
| P1-07 | Cost reporting | `kanon usage` reads Claude Code session logs and fills the Cost section | Totals match independently computed values; an unrecognised log reports "unknown", not zero |
| P1-08 | End-to-end runs | `kanon status`, then `kanon questions`, each through the full loop | Each work file holds every section in committed order; `verify` passes; removing any section fails `verify`; second run compared with first for rounds, questions and tokens |

**Order:** P1-01, then P1-02 and P1-07, then P1-03, P1-04 and P1-06, then P1-05, then P1-08.

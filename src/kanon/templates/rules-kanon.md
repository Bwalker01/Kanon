# Kanon

This project uses Kanon. At the start of every session, run `kanon desk` and read
`kanon/local/DESK.md` and `kanon/local/STATUS.md`. The person's instructions are in
`.claude/rules/kanon-person.md`.

| Path | Contents |
|---|---|
| `kanon/local/` | The person's Desk and project status, generated by `kanon desk`. Never committed. |
| `kanon/docs/roadmap.md` | The phase plan. |
| `kanon/decisions/` | Decision records. The source of truth for decisions. |
| `kanon/work/` | One file per piece of work: Summary, Plan, Questions, Review, Decision, Cost. |
| `kanon/docs/` | Standards, role prompts, learnings and documentation of record. |
| `kanon/archive/` | Superseded documents with reference value. |

Roles, in `kanon/docs/roles/`: Metis coordinates (skill `kanon-metis`), Kritos reviews
(subagent `kritos-reviewer`), Clio records (skill `kanon-clio`), Mnemon keeps context
(skill `kanon-mnemon`), Atlas keeps the person's Desk (skill `kanon-atlas`).

## Rules

1. **Plan first.** Create the work file with `kanon new`, fill its Plan, and commit it on its own before producing anything significant.
2. **Ask early.** Ask when information is missing; record the question and answer in the work file.
3. **Challenge.** Raise flaws, costs and simpler options before acting, with evidence. The person decides.
4. **No self-review.** A separate reviewer, without access to the creator's conversation, reviews all output.
5. **No self-approval.** Set the work file to `awaiting-approval` with a "Decision needed" line, rebuild the Desk and stop. Only an approver listed in `kanon/kanon.toml` approves.
6. **Owner actions.** Anything only the person can do goes in the Actions section of the work that needs it, with steps, as soon as it is known (`kanon/docs/roles/atlas.md`).
7. **Open the Desk** (`kanon/local/desk.html`) for the person whenever a decision or action is waiting.
8. **One file per piece of work.** Revise in place; Git holds earlier versions.
9. **Run `kanon verify`** before committing.
10. **Commit messages** start with ADDED, MODIFIED or REMOVED and give a one-line reason.
11. **Be economical.** Read summaries before full files; run free checks before model reviews.
12. **Delete only what you created.** Make probe folders with `mktemp -d`, keep their exact paths, and remove only those paths. Never delete with `find` or globs over shared folders such as `/tmp` or the home folder; the Kanon guard hook blocks it. The guard reads command text, so if it blocks a harmless command that only contains such text, write that text with a file editor instead.
13. **Never commit personal data.** Profiles stay outside the repository. Generated agent files are listed in the Kanon block of `.gitignore`; `kanon sync` rebuilds them.
14. **Pull requests only through Kanon.** Never open, approve, merge or comment on a pull request with Claude Code's own pull request feature, the GitHub connector or `gh`: they act as the person. Push work to its branch only once every review has passed, and stop; the person opens the pull request as a draft and marks it ready when it is ready to merge (ADR-015), or runs `kanon github pr <work>` on their computer to open it as Kanon's App.
